## Compatible extractions

### PR65: account for the table; drain valid trailing metadata

Initial main allocated its group/pass section table before reading the TOC
and did not charge that storage to the shared memory limit. The extraction defers
allocation until a frame is ready, skips it for header-only scans, reserves
outer and inner table storage together, and releases the charge on reset or
seek. Overflow and budget refusal occur before table allocation.

After the image finishes, leftover bytes inside finite codestream boxes can
hide subsequent Exif. The extraction drains those bytes and continues normal
box parsing, including across `jxlp` parts. It keeps existing parser errors.

The original PR instead suppresses every non-short-read error after entering
the last codestream box. A failing-reader regression demonstrates that this
also hides I/O failures. Independent djxl v0.12 accepts malformed optional
`jhgm`/`jxli` payloads but rejects a duplicate `ftyp`; blanket recovery accepts
that invalid structural box. Only the valid-draining behavior is selected.
The new rejection test covers duplicate `ftyp` and `jxlp` after `jxlc`.

### PR68: propagate CMS failures through existing APIs

Initial main passed one of eight callback-contract tests. RGB/gray callback
failures panicked; CMYK failures silently took a mathematical fallback. Invalid
initializer counts/channels were not consistently rejected, and the CMYK path
hardcoded an sRGB destination rather than forwarding the requested profile.

A private fallible render-stage entry point lets both renderers propagate the
original callback error without rewriting numerical kernels. One validated
CMS stage serves RGB, gray and CMYK, preserves reflectance inputs, validates
initializer results before rendering, and receives the requested destination.
The mathematical fallback remains available when no applicable CMS exists.
No public signature changes, optional MoxCMS interpolation changes or raw-layer
APIs are part of this extraction.

## Work that is not merge-ready

PR60's `Send` bound needs explicit API review. Its old coverage failure is two
diagnostic tests unwrapping missing reference PNGs, rather than a failure of
thread migration. Its corpus checkout must be adapted to main's explicit
reference preparation; copying the old workflow alone is insufficient.

PR61's original performance numbers describe older source and systems. They
do not establish an improvement over today's main. The paired decoder also
passes a bare channel cap where current code requires complete transform
limits. New fallible allocations alone do not satisfy the shared memory
budget: both LUT storage and cache storage need accounting.

PR66 is based on PR65, rather than main. Public `CodestreamLayout`,
`FrameLayout`, `NamedSpan`, recording options and accessors remain absent.
Old qualification is useful historical evidence, but not a current combined
build. Recording hooks run through header parsing even when disabled; their
overhead has not been measured in this review.

PR68's local-layer qualification is intentionally incomplete: negative-origin
pixel fixtures, every blend combination, random raw selection,
preview/reference combinations, progressive raw output, other representations,
and complete callback workspace/time bounds remain unqualified. Its old RGB
[comparison receipt](https://github.com/imazen/zenjxl-decoder/blob/65e3c871b7341703664039fd2ee70e0524f45db6/benchmarks/raw_layer_output_2026-10-26.json) differs from libjxl in 5,485,741 of 18,874,368 float patterns, with
maximum absolute difference 0.00036650896072387695 under the unchanged 1/256
bound. That is historical bounded-error evidence, not bit-exact RGB parity.
CMYK/alpha samples were exact in that historical receipt. The current task
has not rebuilt the public raw-layer changes on main.

## Evidence discipline

The local clone is shallow. Merge bases and unique commit counts were checked
with GitHub's compare API; literal blob diffs use those bases. A local graph
walk of PR61 incorrectly includes older history through merges and is not used
as its unique-change inventory. None of the five complete patches applies
verbatim to the initial main, and patch conflicts alone are not evidence that
a change is missing.

No accuracy threshold, established assertion, or corpus policy is weakened.
No new binary fixture is committed.
